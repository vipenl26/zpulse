What the journalist sends each watcher

One JSON packet per watcher. Nothing in it is secret on its own.

packets/w1.json
{
  "vault_id":     "<16 hex>",
  "watcher_id":   "w1",
  "share_sealed": "<Shamir share, sealed to w1's key>",
  "duress_vk":    "<public half of the second key>",
  "manifest": {
    "threshold": 3,  "n": 5,
    "interval_s": 172800,  "grace_s": 21600,
    "principal_vk":      "<heartbeat signing key>",
    "release_address":   "utest1…",
    "release_ufvk":      "uviewtest1…",
    "release_birthday":  <block height>,
    "ciphertext_sha256": "<hash of vault.bin>",
    "watchers": { "w1": { "address": "utest1…", "vk": "…" }, … },
    "heartbeat_zat": 20000
  }
}

share_sealed is one Shamir share, encrypted to this watcher only. Two of these together still say nothing.

principal_vk and duress_vk let the watcher tell a real heartbeat from a forced one. Only watchers know there are two keys.

manifest is public: the release address and its viewing key, the schedule, the hash of the encrypted file. Anyone can verify a reveal against it.

Sent once, over Signal or in person. After sealing, the journalist deletes the vault key. The laptop no longer holds anything that decrypts the file.

This is the whole handoff: one file per watcher, delivered out of band. Point at share_sealed: it is sealed to that watcher's own key, so even the courier learns nothing. Point at the manifest: it is the public contract, and the same manifest is what the reveal tool checks against. Then say the key line: after seal, the vault key is gone from the journalist's machine.
