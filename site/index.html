zpulse

If I stop checking in, the world reads my files. If someone forces me to check in, the world reads them anyway.

A dead man's switch for journalists and whistleblowers. No server, no recipient, no smart contract. Shielded Zcash memos are the only transport, and the release goes to the world.

01 / the problem

Insurance only works if no one can stop it.

A journalist or whistleblower holds a dossier. Their best protection is that hurting them makes the dossier come out. Existing dead man's switches break in three places.

[ 0x01 ]

Servers get seized.

Most switches are a server somewhere. It can be seized, shut down or quietly reconfigured, and its operator can be leaned on. Whoever controls the box controls whether your files ever leave it.

[ 0x02 ]

Single recipients get pressured.

Other switches hand the file to one recipient: an editor, a lawyer, a friend. One person can be pressured, bribed or silenced. A single point of release is a single point of failure.

[ 0x03 ]

Coercion beats every check-in.

If the threat is "keep checking in or else", a switch that only watches for silence is useless. The adversary simply makes you check in. A real switch has to fire when you are forced to keep it quiet.

02 / how it works

One shielded transaction is the heartbeat.

There is no recipient. Shares go to a public release address whose viewing key is published, so the whole world can reconstruct.

  1. Encrypt and split

    The principal encrypts the dossier with AES-256-GCM and splits the key into n Shamir shares (t-of-n). Each share is sealed to one watcher: an NGO, a lawyer, an editor, a friend abroad. After sealing, the vault key is deleted, so seizing the laptop does not decrypt the vault.

  2. Pulse

    Every interval (48 h in real life, 2 min in the demo) the principal sends one shielded Zcash transaction that pays a few thousand zatoshi to every watcher, with a signed "I'm alive" memo. Those zatoshi fund the watcher's later release, so no watcher ever has to top up a wallet.

  3. Watch, alone

    Each watcher spots the heartbeat with its own wallet only, on a diversified address made for this one vault, so a payment maps 1:1 to a vault. Watchers never talk to each other and run no server.

  4. Release to the world

    If heartbeats stop and the grace period passes, each watcher on its own posts its share as a shielded memo to the public release address. Its viewing key is in the public manifest, so anyone can collect t shares, rebuild the key and decrypt the public ciphertext.

  5. Duress

    A duress heartbeat looks the same on-chain in shape, size and amount, but it is signed with a second key. The attacker sees a successful pulse. Watchers treat it as "release now".

05 / instructions

Run it yourself.

Start with the offline mock chain (under a minute, no wallet, no network). Then run the same CLIs against Zcash testnet. All commands run from the repository root.

requirements install mock demo testnet what each command does troubleshooting

5.1Requirements

  • Python 3.12with cryptography (AES-256-GCM) and pynacl (Ed25519, SealedBox)
  • gitto clone zpulse and zcash-devtool
  • Rust 1.99+ / cargotestnet only: builds the zcash-devtool light client
  • Network to testnet.zec.rockstestnet only: lightwalletd, no full node
  • Testnet ZEC (TAZ)testnet only: ~0.05 TAZ covers a full demo
  • A browseroptional: the live dashboard at 127.0.0.1:8787

5.2Install

shell
git clone https://github.com/vipenl26/zpulse
cd zpulse
pip install cryptography pynacl

5.3Run the offline mock demo

The demo script runs the full flow plus a duress run on an in-process mock chain, and exits non-zero on failure (it doubles as the end-to-end test). ZPULSE_BACKEND=mock is the default.

one shot
demo/mock_demo.sh                                     # full flow + duress run, exits non-zero on failure
python3 dashboard/serve.py --data ./data --port 8787  # open http://127.0.0.1:8787

Step by step, as the demo script runs it:

step by step (mock)
python3 -m zpulse.principal init --name leak --file dossier.txt --threshold 3 --interval 20 --grace 5
for w in w1 w2 w3 w4 w5; do python3 -m zpulse.watcher enroll --id $w --vault data/vaults/leak/vault.json; done
python3 -m zpulse.principal seal --name leak
for w in w1 w2 w3 w4 w5; do python3 -m zpulse.watcher run --id $w --packet data/vaults/leak/packets/$w.json --poll 2 & done
python3 -m zpulse.principal pulse --name leak            # heartbeat (repeat to stay alive)
python3 -m zpulse.principal pulse --name leak --duress   # ...or fire it right now
python3 -m zpulse.principal status --name leak
python3 -m zpulse.reveal --vault data/vaults/leak/vault.json --watch   # anyone can run this

5.4Run on Zcash testnet

Same CLIs with --backend testnet (or export ZPULSE_BACKEND=testnet). Wallets are zcash-devtool wallets under wallet/data/<name>/, server testnet.zec.rocks. Testnet blocks come about every 75 s: use minutes, not seconds, for interval and grace.

  1. 01Build the light client with the patch

    zpulse uses zcash-devtool at commit 0b3436b plus a 14-line patch that adds --min-confirmations to pay.

    shell
    git clone https://github.com/zcash/zcash-devtool wallet/zcash-devtool
git -C wallet/zcash-devtool checkout 0b3436b
git -C wallet/zcash-devtool apply ../zcash-devtool-pay-min-confirmations.patch
cargo build --release --manifest-path wallet/zcash-devtool/Cargo.toml

    Already have a binary? Set ZCASH_DEVTOOL=/path/to/zcash-devtool instead.

  2. 02Select the testnet backend
    shell
    export ZPULSE_BACKEND=testnet
mkdir -p data/logs
  3. 03Create the principal wallet

    Prints the wallet's unified address.

    shell
    python3 wallet/zwallet.py principal init
  4. 04Fund it with testnet ZEC (TAZ)

    Valar faucet gives 0.125 TAZ per IP per day. The Jino Labs faucet (browser proof-of-work) gives 0.1 TAZ per address per day. On 4 Nov 2026 both public faucets were flaky, so a Zcash mentor sending ~0.05 TAZ was the fastest route.

    shell
    python3 wallet/faucet.py <unified address>      # Valar faucet
python3 wallet/zwallet.py principal shield       # only if funds arrived transparent
python3 wallet/zwallet.py principal sync         # sync and print balance
python3 wallet/zwallet.py principal balance

    You need shielded TAZ for n × heartbeat_zat × pulses, plus fees.

  5. 05Init the vault

    Creates the release-<vault_id> wallet and stores its address, viewing key (UFVK) and birthday height in the public manifest. These timings worked on the live run.

    shell
    echo "Dossier: ..." > data/dossier.txt
python3 -m zpulse.principal init --name leak --file data/dossier.txt \
    --threshold 3 --interval 300 --grace 120 --heartbeat-zat 20000
  6. 06Enroll watchers

    Each watcher creates its own wallet (watcher-wN) and a fresh diversified address for this vault.

    shell
    for w in w1 w2 w3 w4 w5; do python3 -m zpulse.watcher enroll --id $w --vault data/vaults/leak/vault.json; done
  7. 07Seal, then pulse immediately

    Seal seals one share to each watcher and deletes the vault key. Send heartbeat #1 right away: the first deadline is sealed_ts + interval + grace.

    shell
    python3 -m zpulse.principal seal --name leak
python3 -m zpulse.principal pulse --name leak       # -> {"txid": ..., "seq": 1, "ts": ...}

    One tx, n shielded outputs, the same signed memo. On the explorer only the tx is visible; amounts and memos are shielded.

  8. 08Start the watchers (after heartbeat #1 is mined)

    Wait 1-3 min for the heartbeat to land in a block, then start them (one terminal each, or in the background). --poll 45 is comfortable on a laptop.

    shell
    for w in w1 w2 w3 w4 w5; do
  python3 -m zpulse.watcher run --id $w --packet data/vaults/leak/packets/$w.json --poll 45 \
     > data/logs/leak-$w.log 2>&1 &
done
python3 dashboard/serve.py --data ./data --port 8787   # optional live view
  9. 09Stay alive

    Pulse again before every interval runs out. Every watcher moves its deadline forward.

    shell
    python3 -m zpulse.principal pulse --name leak
python3 -m zpulse.principal status --name leak
  10. 10Go silent, then reveal

    Stop pulsing. After interval + grace with no new heartbeat, each watcher sends ZP1 SH <vault> <wid> <share> <sig> to the release address. Anyone can then reveal: it imports the release UFVK into a view-only wallet, verifies each share signature against the manifest, and decrypts once threshold distinct watchers have released.

    shell
    python3 -m zpulse.reveal --vault data/vaults/leak/vault.json --watch --poll 60 --timeout 3600
  11. 11Duress

    Looks identical on-chain; watchers release at once.

    shell
    python3 -m zpulse.principal pulse --name leak --duress
  12. 12Cancel

    Watchers mark the vault cancelled and shred their share. A coerced cancel cannot be told apart from a real one; if you fear that, don't use cancel.

    shell
    python3 -m zpulse.principal cancel --name leak

5.6Troubleshooting

  • Memos need enhance.Compact-block sync carries no memo bytes. ZWallet.received() runs zcash-devtool wallet enhance before list-tx; without it every heartbeat reads as "payment with no memo" and the watchers fire at the deadline.
  • Confirmations.The devtool's default spend policy wants 10 confirmations on notes received from others. zpulse calls send/pay with --min-confirmations 1 (env ZCASH_MIN_CONF), which is why the patch is needed.
  • Start watchers after heartbeat #1 is mined.Seal, pulse immediately, then start the watchers once the heartbeat is in a block (1-3 min). A slow block plus early watchers can fire the switch before heartbeat #1 lands.
  • Faucets are flaky.Try the Valar faucet (wallet/faucet.py), then Jino Labs, or ask a Zcash mentor for ~0.05 TAZ. Shield transparent funds with zwallet.py principal shield.
  • release failed, will retry: ... insufficientThe watcher's heartbeat note is not yet spendable (wait 1-2 blocks) or its wallet is unfunded. It retries every poll.
  • reveal sees 0 shares.The view-only wallet may need a full sync from release_birthday. Rerun it; it resumes.
  • Laptop load and sleep.Five watchers running sync + enhance + list-tx every 30 s is heavy; use --poll 45. A sleeping laptop stalls every watcher, and they all release within seconds of waking.
  • State lives on disk.Wallets under wallet/data/, vault state under data/. data/ holds secret keys: keep it out of git.

07 / threat model

What it solves. What it doesn't.

zpulse aims for one property: the dossier becomes public if, and only if, the principal stops sending valid heartbeats (or sends a duress heartbeat), and at least t of n watchers act on it. Before that, no one, including any t-1 watchers, can read it.

handled

  • Coerced check-in: the duress key signs a heartbeat identical in shape, size and amount that tells watchers to release now.
  • Laptop seizure after seal: the vault key is deleted, so the vault cannot be decrypted from it.
  • Seizing fewer than n-t+1 watchers does not stop release; a stolen packet is useless without that watcher's identity.key.
  • t-1 shares reveal nothing (Shamir, information-theoretic).
  • Forged or replayed heartbeats: signed over vault id, seq and ts; seq must increase; deadlines use chain time of the carrying tx.
  • Junk on the release address is ignored: shares must be signed by a watcher key in the manifest.
  • Metadata: shielded txs hide sender, receivers, amounts and memos. Watchers are funded by every heartbeat.

not solved

  • A seized principal key lets the attacker keep the switch alive forever with forged heartbeats.
  • Coerced cancel (if you enable it).
  • t colluding or captured watchers can release early.
  • Watcher liveness relies on people. No on-chain enforcement, no slashing.
  • Timing metadata at the network layer ("a shielded tx every 48 h").
  • Long-term ciphertext hosting: vault.bin must be mirrored (IPFS, torrent, friends).
  • Legal pressure on watchers to not act; spread them across jurisdictions.
  • Hackathon code on testnet. No audit, no side-channel hardening, no secure deletion guarantees. Do not protect a real life with it yet.
